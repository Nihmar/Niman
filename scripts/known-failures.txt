# Tests known to fail on a Windows host, for reasons that are not the
# code. The suite is green on Linux, and as of 2026-09-10 it is green on
# Windows too: the eighteen entries this file used to carry were not
# host quirks after all, and were fixed rather than tolerated.
#
# What they turned out to be:
#   - `Indexer._safeRel` built its library-relative path with the host
#     separator, so the incremental pass wrote `Docs\One.md` for a note
#     the scan had indexed as `Docs/One.md`. A real Windows bug, not a
#     test one: the same note under two paths.
#   - `resolveLibraryRoot` joined an *Android* path with `p.join`, which
#     on Windows spells the separator `\`.
#   - `library_flow_test` compared against a hard-coded POSIX path where
#     the app under test joins with `p.join`.
#   - The Markdown fixtures were checked out with CRLF, and the preview
#     parser choked on a heading ending in a carriage return. Fixed for
#     good by `.gitattributes`.
#   - The 10k-note fixture allowed its scan 60 seconds inside a harness
#     that allows a test 30.
#
# '~' marks a flake: tolerated whether or not it fails on a given run,
# and kept across `newfail.ps1 -Update`. The ones left are the same
# Windows fault under full-suite load — a rename or a delete on a file
# another process still holds ("Accesso negato", errno 5/32). They pass
# in isolation; check a suspect one on its own before believing it. They
# are kept listed because they still fail under load on some runs, not
# because anything is known to be wrong with them.
#
# Do not take that on faith for a '~' entry, though. This file used to
# say the error is never an assertion, and the watcher's "coalesces rapid
# events into a single batch" was the counter-example: it failed its own
# expectation, because the batching window opens when the OS delivers the
# first event and under load the last write of the burst landed after the
# window had closed. It now feeds the watcher a stream the test owns, so
# it no longer depends on when the OS delivers, and the entry is gone
# rather than tolerated (2026-09-11).
