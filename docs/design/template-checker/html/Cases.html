Template checker — the error cases

Every form from the issue's tables, drawn as the checker would report it: the offending span with the wavy mark, the message, and the fix — or, where the issue's boundary says a fix is not safe, a plain “no fix offered”. The messages are illustrative; the engine PR owns the wording, this fixes the shape of a row and of a hint.

Unclosed ‘{{’ — no matching ‘}}’.
No fix offered — at the end of a line there is no }} to close it. A }} further along would close it.

‘}}’ with nothing to close.
No fix offered — there is no opening to match; the text is left as written.
{{title|pad:wide}}
‘pad’ needs a whole number.
Did you mean {{title|pad:3}}?
{{time:HH'|'mm
Unclosed quote in the date format.
Did you mean {{time:HH'|'mm}}?
{{title|+xd}}
‘+xd’ is not a filter this build knows.
No fix offered — a shift count is not a number, and there is no safe default.
{{}}
Empty placeholder.
No fix offered — nothing to name, so nothing to suggest.

The boundary the issue sets is drawn in the third line of each row: a suggestion is proposed only when the fix is computable and safe — a closest known name, a width, a missing brace — and otherwise the row reports the problem and offers nothing. The squiggle is the palette's error, #E0687A, the colour the spelling's own squiggle is drawn in.

The quiet state is the absence of the checker. No banner, no squiggle, no hint — the count line simply is not there (drawn above as the status row with nothing added to it). A line that always reads “Template syntax OK” would be noise on every template that is fine, which is most of them; the strip below it is that variant, drawn only to be rejected. The one place a positive confirmation could earn its room is the moment a template is saved with the checker on, and even there the absence says the same thing.

The checker does not change anything here, and does not need to. The {{ask:…}} and {{choice:…}} answers are filled in the Fill in the template dialog, and that dialog does not edit the template's source — it collects answers, and the source is not editable behind it. There is nothing here to underline and nothing to point at. The checker's feedback belongs to the editor, where the source is: if it runs on save, a template saved with a problem shows its banner the next time the template is opened for editing, not while a note is being made from it. So the two screens do not meet, and this state adds nothing to the drawing beyond saying so.
